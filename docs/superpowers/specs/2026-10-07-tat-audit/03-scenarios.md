# 03 — Scenario audit: Task TAT + daily presence spec (2026-10-07 draft)

Subject: `docs/superpowers/specs/2026-10-07-task-tat-presence-design.md`
Persona company: **Acme Services**, 18 people, IST, run for 4 weeks.
Method: the spec as written, checked against CLAUDE.md §3/§6, the current code
(`middleware/auth.js`, `authController.js`, `taskController.js`,
`web/src/utils/axiosConfig.js` + `endSession.js`, `mobile/src/api/client.ts`,
`mobile/src/stores/useAuthStore.ts`) and read-only queries on the live eCRM+ DB.

## 0. Facts from the code/DB that the spec does not account for

| # | Fact | Source | Why it matters |
|---|---|---|---|
| F-a | `sp_RecomputeTaskCompletion` sets complete only when `@Total > 0 AND @Open = 0`. **A task with zero checklist items can never complete.** Live: 2 of 39 tasks have no checklist. | `sys.sql_modules` | Its clock never closes → guaranteed resolution breach. |
| F-b | `sp_DeleteTaskChecklist` also calls the recompute. Deleting the last *open* item completes the task. | `sys.sql_modules` | Completion without doing the work (gaming vector). |
| F-c | On un-complete, `CompletedDate` is set to NULL; re-complete stamps a new `GETDATE()`. | same | Reopen/re-complete semantics for clocks must not read `CompletedDate` history. |
| F-d | `tblTasks.DueDate` already exists and is used: **26 of 39** live tasks carry one; `sp_SaveTask` overwrites it on every update. | DB + `taskController.save` | Spec introduces a second deadline (`ResolutionDueAt`) and never mentions the first. |
| F-e | `tblTasks.IsBlocked` exists; `sp_ResolveDependencies` clears it when blockers complete. | DB | Spec never pauses a clock for a blocked task. |
| F-f | `sp_SaveTask`'s 2nd result set returns only **added** assignees (`NewAssigneeUserId`). Removals are not reported. | DB + `taskController.save` | F4 "closed with `unassigned` when the assignee is removed" has no signal to hang on. |
| F-g | Clock opening is planned in the controller *after* the SP commits (F4). The existing notify call after the SP is fire-and-forget (`.catch(console.error)`). | `taskController.save` | A crash/timeout between commit and clock insert leaves an assignee with no clock, silently. |
| F-h | `sp_DeleteUser` refuses users with assignments; leavers are therefore deactivated, not deleted. | DB | No path in the spec closes a leaver's clocks or stops their "Not signed in". |
| F-i | DB server tz = IST; container pinned `TZ: Asia/Kolkata`, `useUTC:false`. | `docker-compose.yml`, `database.js` | OK in prod; `workCalendar.js` tests on a UTC CI/laptop will lie unless the module never uses local-time `Date` getters. Two clocks (Node `@Now` vs SQL `GETDATE()`) still both write stamps. |
| F-j | Web `endSession` is a **hard redirect** that discards the document; the message is always "Session expired". Mobile 401 handler silently `logout()`s with no message. | `endSession.js`, `client.ts`, `useAuthStore.ts` | A forced/expired session destroys unsaved work (quotation builder) and cannot say *why*. |
| F-k | Heartbeat (F3) only *updates* `tblUserSession.LastSeenAt/LastActiveAt`. No history is kept. | spec | Nothing exists to settle a dispute ("I was working"), and no active-minutes report is possible. |

## 2. Spec contradictions

1. **"Never past 23:59"** (F2) vs **overnight shifts** tested in §8 and a night-shift user. A 21:00–06:00 shift cannot exist under a 23:59 session cap and a presence day keyed by calendar date.
2. **§1 Q1 "signed in and become active by shift start"** vs F3 which computes Late from `FirstSignInAt` only.
3. **D5 "one slow person must not mark the other late"** vs F4 completion being task-level (checklist). For resolution, a slow co-assignee does mark the other late.
4. **"1d = one shift"** vs **targets stored in working minutes** with per-user calendars of different lengths (part-timers 4 h, Saturday half-days).
5. **"Null target = no clock"** vs null override meaning "use the company default".
6. **Existing `tblTasks.DueDate`** (used on 26/39 tasks) vs new `ResolutionDueAt`: two deadlines, the spec names one.
7. **F4 "closed with `unassigned` when the assignee is removed"** vs `sp_SaveTask` reporting only *added* assignees.
8. **F4 hold: "anyone who can edit the task"** vs CLAUDE.md §6 (a member edits only their own tasks) → the assignee usually cannot hold, yet D3 sells On hold as the employee's fair alternative to Pause.
9. **D8 "app open"** vs F3 "heartbeat while the app is in the foreground" (undefined for a web tab).
10. **F5 verdict "or a workspace owner/manager"** vs a manager who is the assignee (self-excuse).
11. **CLAUDE.md §6 "Personal = private even from admins"** vs F7 manager Today counts, F8 reports, F6 `ReportsTo` breach notifications.
12. **F3 "one row per working day"** vs sign-ins on non-working days and night shifts spanning two dates.
13. **Seeded breach reason "Unplanned leave"** vs no leave concept at all — the spec admits the gap in its own seed data.
14. **§8 risk "calendar edited mid-day: presence frozen at sign-in"** vs the not-signed-in check, which runs before any row exists and so reads the live calendar.
15. **D9/F10** reverse CLAUDE.md §6 ("no business hours … `TatHours` is the whole of it"). Intended, but CLAUDE.md must change in the same PR or the next agent will "fix" it back.

## 3. Missing concepts

| Concept | Why it is needed | Minimal shape |
|---|---|---|
| **Leave** (full, half, sick/retroactive) | Without it, every leave day produces false absence, manager spam and breaches that must be excused one by one. **Fatal for a WFH presence feature**: the first week of real use generates more false positives than true ones. | `tblUserLeave(CompId, UserId, LeaveDate, Part full/first_half/second_half, TypeId lookup, Remarks, EnteredBy, EnteredAt)`. | **Blocked = system hold** | Dependencies. | Hold opened/closed by `IsBlocked` transitions. |
| **Deactivation handling** | Leavers. | Close clocks `user_left`, force-end sessions, stop presence. |
| **Notification grouping** | 20 breaches at 10:25. | One per recipient per kind per tick. |
| **Notification outbox** | Restart between stamp and notify. | `NotifiedAt`. |
| **TAT change log** | Priority/target/DueDate edits, reopen, reassign. | Rows in `tblActivityLog` with old→new; shown on TAT tab. |
| **Go-live date** | Deploy-day false lates. | Company setting. |
| **Display timezone** | Dubai user, any device in another zone. | Render in company zone with "IST". |

| **Retention** | Spec is silent. | Sessions: 13 months. Presence days and TAT rows: kept (they are the record). If a raw heartbeat log is ever added: 18 users × 30 beats/h × 9 h × 365 ≈ **1.77 M rows/year** (×2 with phone+laptop) — fine for SQL Server but pointless; the counters on `tblPresenceDay` (rule 14) replace it. Today's design (UPDATE only) is ~540 single-row updates/hour: negligible. |

## 4. Gaming vectors and mitigations

| # | Vector | Who | Mitigation |
|---|---|---|---|
| G1 | Mouse-jiggler / tab left open / scripted heartbeat to look Active | Employee | Do not show Active vs Idle to anyone or report it (rule 12). Online/Offline only. |
| G2 | Sign in from phone at 09:58, start work at 11:30 | Employee | Show `FirstOnlineAt` beside sign-in; accept that sign-in is a check-in, not proof of work. |
| G3 | Press Start on everything instantly | Employee | Response becomes "Acknowledged", not a performance metric; resolution is the metric. |
| G4 | Put everything On hold (once assignees can hold) | Employee | Reason + remarks, manager notified at once, auto-release after 3 working days, held-minutes per person in reports. |
| G5 | Delete open checklist items to complete | Employee (creator) | Restrict deleting open items on assigned tasks; log it. |
| G6 | Tick all items at once at the end | Employee | Accept; TAT measures completion time only. |
| G7 | Creator-assignee sets null/huge target or lowers priority on own task | Employee | Overrides by non-assignee only; changes logged; "tasks with custom/no clock" column in report. |
| G8 | Reassign an at-risk task away (or A→B→A) to reset the clock | Manager | Re-add within 7 days continues old row; "reassigned while at risk" in report. |
| G9 | Excuse a favourite's breaches | Manager | Remarks required; excused % by verdict giver in the breach-reasons report; verdict history kept. |
| G10 | Excuse own breaches | Manager-assignee | No self-verdicts (rule 39). |
| G11 | Delete a late task (or bulk-delete) to clear the record | Manager/creator | Breach still counts; "deleted after breach" with actor. |
| G12 | Un-tick a completed task to manufacture a breach | Anyone with change_status | Reopen gets fresh remaining time (rule 29); reopen actor shown. |
| G13 | Retroactive leave to erase breaches | Employee/Manager | Self-entered leave after the fact is visible as "entered late" (EnteredAt > LeaveDate) and its excusal is `pending` verdict, not auto-excused; manager/admin-entered leave auto-excuses. |
| G14 | Set a long `DueDate` to avoid the priority clock | Manager/creator | Allowed (it is the assigner's call), but visible on the task and the report shows target vs default. |

## 5. Fairness of reports (F8)

- Breach **count** punishes volume. Lead with **on-time %** and show the denominator (clocks) next to it; break down by priority (a person fed 20 criticals is not comparable to one fed lows).
- Exclude from the denominator: clocks closed `unassigned`/`user_left`/`deleted` **before** breach. Include breaches on closed clocks.
- Averages of response/resolution are dominated by one stuck task — report **median** and p90, not mean.
- Show both "breached" and "breached, not excused"; `Reason pending` counts as not excused (as specced) but is labelled separately so a missing reason is not read as a bad reason.
- Attendance: "working days" must subtract leave and holidays, and per-user calendar history (rule 11).
- Self scope: an employee can open their own rows of every report. Nothing the manager sees about a person is hidden from that person.

## 6. Accessibility and copy

- Chips rely on green/amber/red. Each needs text + icon ("12m left", "At risk · 6m", "Breached 25m", "On hold") — never colour alone. Check contrast of amber text on surface (WCAG AA 4.5:1).
- Live countdowns must not tick every second inside an `aria-live` region; update per minute, `aria-live="off"`, with a static "Due 10:25 IST" in the accessible name.
- Copy: "Idle *n* min" and "Not signed in" read as accusations on a team page. Use "Offline", "Not signed in yet", "On leave", "Holiday". "Late by *n* min" is shown to the person and their chain only.
- "Response" → "Acknowledged"; "Resolution" → "Done by".
- Session-ended messages per reason: "Your working day ended at 21:00 — sign in again to continue", "An admin ended your session", "You signed out on this device".
- HelpGuide (EN/हिंदी) entry for the Today page explaining exactly what is recorded.

## 7. Recommended spec changes (paste-ready)

1. **Add leave (F1a).** New table `tblUserLeave(CompId, UserId, LeaveDate, Part ['full','first_half','second_half'], TypeId → tblLookup Kind='leave_type', Remarks, EnteredByUserId, EnteredAt)`. Entered by the user (visible to their chain) or by a manager/admin in the user's `ReportsTo` chain. `workCalendar.js` takes per-user leave as non-working intervals. A leave day produces no Late/Not-signed-in mark and no manager notification. Entering leave for a past date: open clocks extend by the leave's working minutes; breaches stamped inside the leave window get reason `leave` and verdict `excused` (system) when entered by a manager, `pending` when self-entered.
2. **Shift instances.** A shift instance belongs to the date it starts; end < start means it ends the next day. A sign-in is attributed to the instance whose window `[start − 4 h, end + buffer]` contains it. `tblPresenceDay` is keyed by (UserId, ShiftStartDate). Delete "never past 23:59".
3. **Session expiry.** Expiry = the attributed instance's `end + buffer`, extended while the session is actively used, never past the next instance's window start. Outside any window: until the next window starts. No session spans two shift instances.
4. **Session-ended UX.** 401 bodies carry `code` = `SESSION_EXPIRED` / `SESSION_FORCED` / `SESSION_LOGGED_OUT`. Web: a re-sign-in modal over the current page that retries on success; no hard redirect while any form is dirty; admin force-end redirects after a 60-s notice. Mobile: login screen shows the reason. The quotation builder keeps a local draft.
5. **Presence status (F3).** Manager-visible states: Online · Offline · Signed out · Not signed in yet · On leave · Holiday · Late by *n* min. "Idle" is not shown to anyone and not stored for reports. `tblPresenceDay` gains `FirstOnlineAt`, `OnlineMinutes` (server-incremented, ≤ 2 per beat, beats < 60 s apart per session ignored). Web beats while the page is open at any visibility; one beat per session across tabs.
6. **Presence aggregation.** A user is Online if any open session was seen ≤ 5 min. `FirstSignInAt` = earliest sign-in across devices in the instance window.
7. **Presence adjustments.** `tblPresenceAdjustment(PresenceDayId, Kind ['on_duty','outage','leave','holiday','other'], Remarks, ByUserId, At)`, append-only, by the user's `ReportsTo` chain or admin, visible to the user. Reports read adjusted values.
8. **Retroactive holiday.** Adding a holiday that covers a past or current minute recomputes presence for that date and system-excuses breaches stamped inside it; open clocks extend.
9. **Go-live date** company setting. No presence or TAT is recorded before it. Ship the `sid` change before shift start.
10. **Personal workspaces have no TAT.** No clocks, no chips from TAT, no Today counts, no reports, no notifications for tasks in a `personal` workspace (CLAUDE.md §6).
11. **DueDate is the resolution target when set.** `ResolutionDueAt` = `DueDate` (end of the assignee's shift on that date if date-only); priority defaults apply only when `DueDate` is null.
12. **Target columns.** `ResponseTargetMinutes`/`ResolutionTargetMinutes`: NULL = company default, `0` = no clock. Seed medium resolution as 480 working minutes, described as "8 working hours", not "1 day".
13. **Changes to priority, targets or DueDate** recompute due times of open, unbreached clocks anchored at `AssignedAt` plus held minutes; if the result is already past, due = now + 30 working minutes. Breached clocks are untouched. Each change is logged (old → new, by) and shown on the TAT tab. Only someone other than the assignee may change them, unless they are the workspace owner/manager.
14. **Clock rows are written in `sp_SaveTask`.** It opens `tblTaskTat` rows for added assignees (due NULL) and closes rows for removed ones (`unassigned`), in its transaction. The controller fills due times via `workCalendar.js`; the sweep fills any row still NULL. Filtered unique index: one open row per (TaskId, UserId). Re-adding a user within 7 days reopens their previous row.
15. **Blocked = system hold.** `IsBlocked` 0→1 opens a hold (reason `blocked_by_dependency`), 1→0 releases it. Holds may be opened by the assignee on their own clock (reason + remarks, manager notified at once, auto-release at the end of the 3rd working day), by the creator, or by a workspace owner/manager.
16. **Completion.** A task with zero checklist items has no resolution clock (chip: "Add a checklist to start the clock"). Each assignee may mark "My part is done", which closes only their clock. Task completion closes the rest. Deleting an open checklist item on an assigned task requires workspace owner/manager or a creator who is not the assignee.
17. **Reopen.** A reopened clock gets `ResolutionDueAt = reopenAt + max(remaining working minutes at completion, 60)`; the reopen and its actor are logged.
18. **Response is "Acknowledged".** Stopped by Start or by the assignee's first write on the task. It is shown but not used as a performance metric; reports lead with resolution.
19. **Viewers cannot be assignees** (400).
20. **Deactivation** force-ends all sessions, closes open clocks with `user_left` (excluded from on-time %), stops presence from that date.
21. **Delete.** `sp_DeleteTask` and `sp_BulkDeleteTasks` close clocks with `deleted`; breaches on them still count; `tblTaskTat` snapshots the task title; reports show "deleted after breach" and by whom.
22. **Verdicts.** Only a `ReportsTo` ancestor of the assignee, or a workspace owner/manager who is not the assignee, may give a verdict. Never one's own. `excused` requires remarks. One edit allowed; both versions kept. The breach-reasons report breaks excused % down by verdict giver.
23. **Sweep reliability.** Every stamp comes from SQL `GETDATE()` (`@Now` is a test seam only). Stamped rows carry `NotifiedAt`; the sweep notifies rows with `NotifiedAt IS NULL`, then stamps it. Notifications are grouped: one per recipient per kind per tick. Managers get breaches only, not warnings.
24. **Time display.** Every TAT/presence time renders in IST with an "IST" suffix on both clients, whatever the device zone. `workCalendar.js` uses fixed +05:30 arithmetic and never `Date` local getters; its tests run under `TZ=UTC` and `TZ=Asia/Dubai`.
25. **Calendars.** Weekday rules may carry weeks-of-month (alternate Saturdays). `tblUserCalendar(UserId, CalendarId, FromDate)` replaces a bare `tblUser.WorkCalendarId` so history survives a move. The not-signed-in check reads the calendar as it stood at the shift start.
26. **PresenceExempt** users are omitted from Today presence rows and the Attendance report.
27. **Reports.** On-time % with the clock count beside it; per-priority breakdown; median and p90 instead of averages; "breached" and "breached, not excused" side by side; working days net of leave and holidays. Employees see their own rows in every report.
28. **Transparency and retention.** One-time notice at first sign-in after go-live stating what is recorded, who sees it, how long it is kept. Sessions kept 13 months; presence days and TAT rows kept as the record; no raw heartbeat log.
29. **Accessibility/copy.** Chips carry text + icon, not colour alone; countdowns update per minute outside `aria-live`; neutral copy ("Offline", "Not signed in yet"); HelpGuide entry in EN/हिंदी for Today.
30. **CLAUDE.md §6** is updated in the same change to record that D9 reverses the 2026-07-16 "no business hours" decision.
